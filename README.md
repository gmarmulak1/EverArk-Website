# EverArk website

The marketing site for EverArk — a standalone static site, migrated off Weebly.

139 pages of flat HTML plus their assets. There is no bundler and no framework:
the repository is what gets served.

## Working on it

```sh
npm install
npm run dev          # http://localhost:8080, resolves URLs the way a static host does
```

**Edit `src/`, not the root `.html` files** — those are build output. Each page
is one file in `src/pages/` with a front matter block; the header, footer and
`<head>` boilerplate live once in `src/partials/`. See
[src/README.md](src/README.md).

```sh
npm run build        # src/ -> the root .html pages, search index, sitemap, robots.txt
```

## Verifying a change

The site's design is inherited from Weebly and is meant to stay put, so changes
are checked rather than eyeballed.

```sh
npm run verify                            # round-trip + links + 33 behavioural checks
npm run verify:requests                   # load every page, prove nothing calls Weebly

node tools/verify/capture.mjs before      # screenshot every page at 3 widths
#   ...make the change...
node tools/verify/capture.mjs after
node tools/verify/compare.mjs before after   # pixel diff + HTML report
```

`npm run verify` starts with the round-trip check: every page is rebuilt from
`src/` and compared to the committed output **byte for byte**, so a template
change that alters any page fails loudly.

`links.mjs` is instant and offline. `requests.mjs` drives a real browser over
all 141 pages, so it is a pre-deploy check rather than a per-edit one; `PAGES=n`
samples the first n.

`capture.mjs` also takes `BLOCK=<regex>`, which aborts matching requests — the
quickest way to answer "is this script actually load-bearing?" without editing
a page — and `IMAGE_WAIT_MS`, which is worth raising when the two builds differ
a lot in weight, so a lazy image still in flight at the cap does not show up as
a difference the change did not cause.

`carousel-probe.mjs` is the same idea for behaviour rather than pixels: it
records what the carousel does at six widths — slides per set, dots, geometry,
autoplay, what a resize changes — and `--diff` compares two runs field by
field.

```sh
node tools/verify/carousel-probe.mjs before
#   ...make the change...
node tools/verify/carousel-probe.mjs after
node tools/verify/carousel-probe.mjs --diff before after
```

## Layout

```
src/pages/                 one file per page: front matter + its own content
src/partials/              the chrome every page shares
*.html                     BUILD OUTPUT — regenerated by npm run build
assets/js/                 site runtime: forms, search, carousel, configuration
assets/vendor/             third-party CSS/JS/fonts, mirrored by host and path
assets/search-index.json   generated from the pages by the build
assets/nav.json            the navigation structure
files/                     theme CSS and scripts (from the original Weebly theme)
uploads/                   images
tools/build/               the build: src/ -> pages, search index, sitemap
tools/verify/              round-trip, link, behaviour, request and screenshot checks
tools/migrate/             the one-time Weebly conversion, kept for provenance
_archive/                  export debris, served by nothing — see MIGRATION.md
```
