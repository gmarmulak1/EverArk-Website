# EverArk website

The marketing site for EverArk — a standalone static site, migrated off Weebly.

139 pages of flat HTML plus their assets. There is no bundler and no framework:
the repository is what gets served.

## Working on it

```sh
npm install
npm run dev          # http://localhost:8080, resolves URLs the way a static host does
```

Edit the `.html` files directly. Anything derived — the search index, the
sitemap, `robots.txt`, the favicons — is regenerated by:

```sh
npm run build
```

That command runs `tools/migrate/run-all.mjs`, which is also the full migration
pipeline. Every step is idempotent, so running it against an already-migrated
tree only refreshes the generated files.

## Verifying a change

The site's design is inherited from Weebly and is meant to stay put, so changes
are checked rather than eyeballed.

```sh
node tools/verify/links.mjs               # every local href/src/url() resolves
node tools/verify/interactions.mjs        # 19 behavioural checks
node tools/verify/requests.mjs            # load every page, prove nothing calls Weebly

node tools/verify/capture.mjs before      # screenshot every page at 3 widths
#   ...make the change...
node tools/verify/capture.mjs after
node tools/verify/compare.mjs before after   # pixel diff + HTML report
```

`links.mjs` is instant and offline. `requests.mjs` drives a real browser over
all 141 pages, so it is a pre-deploy check rather than a per-edit one; `PAGES=n`
samples the first n.

`capture.mjs` also takes `BLOCK=<regex>`, which aborts matching requests — the
quickest way to answer "is this script actually load-bearing?" without editing
a page.

## Layout

```
*.html                     the pages
assets/js/                 site runtime: forms, search, configuration
assets/vendor/             third-party CSS/JS/fonts, mirrored by host and path
assets/search-index.json   generated from the pages by the build
assets/nav.json            the navigation structure
files/                     theme CSS and scripts (from the original Weebly theme)
uploads/                   images
tools/migrate/             the migration pipeline, one numbered step at a time
tools/verify/              screenshot and behaviour harnesses
_archive/                  export debris, served by nothing — see MIGRATION.md
```
